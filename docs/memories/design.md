# 项目设计

## 项目目标

- 监听 Telegram 消息。
- 把消息归档到本地 Markdown 和 JSON。
- 把消息主数据写入 SQLite。
- 只对指定频道执行社交媒体同步。
- 把处理结果回发给目标用户。

## 核心输入与输出

- 输入：Telegram update。
- 输出 1：本地归档文件。
- 输出 2：数据库消息记录。
- 输出 3：可选的社交媒体同步结果。
- 输出 4：Telegram 通知消息。

## 核心行为

### 归档

- 每条消息单独存档。
- 存档路径固定为 `archives/<bucket>/<source_id>/<file_name>`。
- `bucket` 只允许 `channel` 或 `person`。
- `source_id` 优先使用频道 username；没有时使用 chat id；统一小写。
- `file_name` 默认回退为 `message_id.md`，也允许通过 `template.file_name_template` 自定义。
- `title` 不来自 Telegram 原生字段，当前固定取正文归一化后的前 20 个字符；为空时回退到 `message_id`。
- Markdown 完整内容由 `config/template.txt` 统一输出，front matter 不再在服务里硬编码拼接。
- 重复消息优先依赖数据库唯一约束判断。

### 历史 JSON 补录

- 当前支持离线扫描 `archives/json` 中的历史 Telegram update JSON。
- 补录命令固定为 `tg migrate json-to-db`。
- 历史补录只写消息主数据到 SQLite，不重写 Markdown，不补抓附件，不触发同步。
- 历史补录的 `CreatedTime` 优先取 JSON 文件修改时间，取不到时回退到消息时间。
- 历史补录必须可重复执行；重复消息固定记入 duplicates，不作为致命失败。

### 同步

- 只有 `socialMediaSync.enable: true` 时才考虑同步。
- 只有消息来源精确命中 `socialMediaSync.targetChannel` 时才同步。
- 当前支持纯文字和图片同步；普通消息最多 1 张图，相册聚合消息支持多图。
- 相册消息（`media_group_id` 非空）按静默窗口聚合整组，只发一次；平台单帖最多 4 张图，超出部分按线程续发。
- 图片上传失败时，优先降级为纯文字同步。
- 未命中时，不做平台分发，只记录跳过原因并通知。
- 每次平台分发结果都要按“消息 x 平台 x 尝试次数”写入独立同步记录。
- 同步记录保留完整历史，不覆盖旧尝试。
- 成功同步时优先记录远端链接；无公开链接时记录远端追踪标识。
- 当前平台发送前会统一执行文本预处理与按平台上限截断。
- 当前文本长度口径固定为：Twitter 按全角 2、半角 1 的加权规则；Mastodon 和 BlueSky 继续按 grapheme 级。
- 当前平台文本上限固定为：Twitter 280，Mastodon 500，BlueSky 300。
- 当前平台结果返回结构已固定，不再使用纯布尔结果驱动后续链路。

### 通知

- 归档结果要通知。
- 同步结果要通知。
- 同步通知要区分“图文成功”“图片跳过”“平台失败”。
- `targetUserList` 为空时，回退到消息来源聊天。
- 当前同步通知已能表达“文本已截断”和更具体的失败原因。

### 管理交互

- 第一版管理交互固定为按钮式，不依赖命令参数驱动页面跳转。
- 管理视图固定为 4 层：管理首页、来源列表、消息列表、消息详情。
- 管理首页固定展示：消息总量、来源总数、可同步频道数。
- 来源列表固定展示：来源标识、归档数量、是否命中同步配置。
- 消息详情固定展示：归档状态、来源链接、各平台同步状态、各平台外链、最近一次同步结果。
- 重同步粒度固定为单个平台或当前消息下全部平台，不做批量重同步。
- 管理读取能力已收口到独立查询服务，bot 层后续只消费稳定输出模型。
- 当前管理查询已固定支持两个筛选口径：仅看可同步频道、仅看同步异常消息。
- 当前 Telegram 管理页已落地基础按钮导航和原地编辑刷新。
- 当前 `/admin` 与 `/start` 都能进入管理首页。

### 手动重同步

- 当前手动重同步固定复用数据库中的归档消息正文与首张图片附件路径。
- 当前手动重同步只允许来源命中 `socialMediaSync.targetChannel` 的消息执行。
- 当前手动重同步支持“全部平台”与“单个平台”两种粒度。
- 当前对同一消息同一范围的手动重同步已加最小防重入门禁。
- 手动重同步结果写回同步记录时，触发方式固定记为 `manual`。
- 当前管理页重同步结果反馈已能显示平台结果与截断状态。

## 冻结决策

- 唯一配置源是 `config/config.yaml`。
- 不使用环境变量覆盖配置。
- 频道匹配只做精确匹配，不做模糊匹配、正则或通配符。
- 主流程保持 `archive -> sync -> notify`。
- 当前默认执行模式是串行；异步只允许实验性开关控制。
- 历史 `notification` 配置块视为废弃，不再扩展。

## 归档最小规范

- Markdown 文件必须带 YAML front matter。
- 文件路径中的 `bucket`、`source_id` 必须和文件内容一致。
- 文件名允许模板化，但必须能由同一条消息稳定复现。
- 默认文件名模板是 `{{.id}}-{{.title-filename-truncated}}.md`；未配置时回退到 `message_id.md`。
- 每条消息的稳定键是 `(chat_id, message_id)`。
- `source_id` 超过 128 个字符时直接报错，并进入通知流程。

## 非目标

- 不做多版本归档规范并存。
- 不做灰度切换和双写。
- 不在文档里保存历史实施过程。
- 不把实现计划、回归记录、迁移细节放进 memories。
- 不在本轮引入 Web 管理后台或复杂权限系统。
